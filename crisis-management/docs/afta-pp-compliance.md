# انطباق با پروفایل حفاظتی «برنامه‌های کاربردی تحت شبکه» (افتا، نسخه ۱.۱ — اسفند ۹۶)

این سند برای هر الزام پروفایل حفاظتی (مبتنی بر ISO/IEC 15408 — معیار مشترک) نشان می‌دهد که در «سامانه مدیریت بحران شهری» چگونه پیاده‌سازی شده، کجای کد است و کدام آزمون خودکار آن را می‌سنجد. این سند پایه بخش «خلاصه مشخصات محصول» (ASE_TSS) در سند هدف امنیتی است.

- محصول مورد ارزیابی (TOE): سرور API، کنسول مدیریت وب (`/console`) و اپلیکیشن (`/app`) در پوشه `crisis-management/`.
- محیط عملیاتی: سیستم‌عامل سرور، PostgreSQL، پراکسی/فایروال، سرویس api.ir (شاهکار و پیامک)، ساعت NTP، پشتیبان‌گیری.
- آزمون‌ها: `test/afta.test.ts` (الزامات این پروفایل)، `test/console.test.ts`، `test/app-auth.test.ts`، `test/operations.test.ts`، `test/apiir.test.ts` — مجموعاً ۵۴ آزمون روی PostgreSQL واقعی.
- علامت‌ها: ✅ پیاده‌سازی و آزموده‌شده · 🟦 پیاده‌سازی‌شده، وابسته به پیکربندی استقرار · 🟨 بر عهده محیط عملیاتی (با راهنما)

## انتخاب‌ها و اختصاص‌های سند هدف امنیتی

| مورد | انتخاب در این محصول |
|---|---|
| نقش‌ها (FMT_SMR.1) | مدیر امنیت و کاربران، ممیز امنیتی، مدیر فنی، مدیر بحران، مسئول اتاق عملیات، کارشناس عملیات، رابط منطقه، امدادگر، ناظر، شهروند + نقش‌های سفارشی؛ **هر حساب دقیقاً یک نقش** (نکته کاربردی ۱۹) |
| سازوکارهای احراز هویت (FIA_UAU.5.1) | نام کاربری و رمز؛ OTP پیامکی (api.ir SmsOTP)؛ تطبیق کد ملی و موبایل با **شاهکار** (api.ir ShahkarPro)؛ توکن دستگاه ثبت‌شده؛ گواهی X.509 کاربر (اختیاری، mTLS) |
| احراز چندعاملی کاربران راه دور (FIA_UAU.5.2) | کنسول: رمز + OTP. اپ: ورود اولیه شاهکار + OTP، ورودهای بعدی دستگاه ثبت‌شده (توکن صادرشده سرور) + OTP |
| اقدامات پیش از احراز هویت (FIA_UAU.1.1) | مشاهده راهنمای ورود، شناسایی کاربر؛ بازیابی خودکار رمز وجود ندارد (بازنشانی توسط مدیر امنیت) |
| اقدام پس از آستانه تلاش ناموفق (FIA_AFL.1.2) | قفل حساب؛ با قفل‌های متوالی مدت قفل دو برابر می‌شود (حداکثر ۲۴ ساعت) |
| پر شدن ممیزی (FAU_STG.4) | جلوگیری از رویدادهای قابل ممیزی به جز رویدادهای کاربران مجاز با حقوق ویژه (ممیز امنیتی و مدیر امنیت) — قابل تغییر به «فقط هشدار» |
| تشخیص/جلوگیری تغییر ممیزی (FAU_STG.1.2) | هر دو: جلوگیری (تریگر پایگاه داده) و تشخیص (زنجیره HMAC-SHA256) |
| الگوریتم صحت (FCS_COP.1(1)) | HMAC-SHA256 با کلید ۲۵۶ بیتی — FIPS 198-1 / FIPS 180-4 |
| درهم‌سازی (FCS_COP.1(2)) | SHA-256 (FIPS 180-4) برای چکیده‌ها؛ رمز عبور با bcrypt |
| مسیر امن (FTP_TRP.1) | HTTPS روی TLS 1.2 |
| مجموعه رمزهای TLS سرور (FCS_TLSS_EXT.1.1) | `TLS_ECDHE_ECDSA/RSA_WITH_AES_128/256_GCM_SHA256/384` و `TLS_ECDHE_ECDSA/RSA_WITH_AES_128_CBC_SHA256/AES_256_CBC_SHA384` |
| به‌روزرسانی (FPT_TUD_EXT.1.2) | به‌روزرسانی دستی توسط مدیر سیستم پس از اطمینان از امنیت بسته (امضای دیجیتال + چکیده منتشرشده) |
