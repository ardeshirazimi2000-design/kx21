# هوش مصنوعی روی سرور خود سازمان (Ollama + Qwen2.5 7B)

خلاصه نامه‌های وارده («شرح نامه»)، خلاصه نتایج و گسترش موضوع در جستجوی هوشمند به یک مدل گفتگو نیاز دارند. با این راه‌اندازی، مدل **Qwen2.5 7B** با Ollama روی همین سرور اجرا می‌شود:

- **متن نامه‌ها از سرور بیرون نمی‌رود.** به اینترنت، کلید API یا سرویس خارجی هم نیازی نیست.
- موتور هیچ پورتی روی سرور باز نمی‌کند و فقط کانتینرهای همین سامانه به آن دسترسی دارند (`http://ai:11434/v1`).
- این موتور همان سرویس `ai` در `docker-compose.yml` است. سامانه جلسات هم برای «مصوبات مشابه» از آن استفاده می‌کند، پس یک نصب برای هر دو سامانه کافی است.
- **قاعده نامه‌های طبقه‌بندی‌شده تغییری نکرده است.** این نامه‌ها حتی به مدل محلی هم فرستاده نمی‌شوند.

## پیش از نصب: منابع سرور

```bash
free -h          # ستون available: دست‌کم ۶ گیگابایت آزاد
nproc            # تعداد هسته‌ها؛ هرچه بیشتر، سریع‌تر
grep -c avx2 /proc/cpuinfo   # صفر یعنی پردازنده (یا ماشین مجازی) AVX2 را نشان نمی‌دهد و مدل بسیار کند می‌شود
df -h /var/lib/docker        # حدود ۷ گیگابایت فضای آزاد (مدل گفتگو ۴٫۷ و bge-m3 حدود ۱٫۲ گیگابایت)
docker stats --no-stream     # مصرف حافظه سامانه‌های دیگر روی همین سرور
```

| مدل | حافظه لازم | کیفیت فارسی | زمان تقریبی خلاصه یک نامه روی CPU |
|---|---|---|---|
| `qwen2.5:7b` (پیشنهادی) | حدود ۶ گیگابایت | خوب | ۲۰ ثانیه تا ۲ دقیقه |
| `qwen2.5:3b` | حدود ۳ گیگابایت | متوسط | چند برابر سریع‌تر |
| `bge-m3` (embedding، اختیاری) | حدود ۱٫۵ گیگابایت | — | برای رتبه‌بندی معنایی نتایج جستجو |

- خلاصه نامه در پس‌زمینه ساخته می‌شود و کاربر منتظر آن نمی‌ماند.
- Ollama مدل را پس از ۵ دقیقه بیکاری از حافظه خارج می‌کند (`AI_KEEP_ALIVE` در `.env`). در این مدت حافظه برای سامانه‌های دیگر آزاد است. درخواست بعدی مدل را در چند ثانیه دوباره بارگذاری می‌کند.
- اگر ماشین مجازی Hyper-V است و AVX2 دیده نمی‌شود: ماشین را خاموش کنید و در تنظیمات Processor گزینه «Processor compatibility» را بردارید.

## نصب

```bash
cd ~/kx21 && git pull
bash deploy/ai/office-llm.sh
```

اسکریپت این کارها را انجام می‌دهد:

1. حافظه آزاد را بررسی می‌کند. اگر کمتر از ۶ گیگابایت باشد، متوقف می‌شود و گزینه‌های دیگر را پیشنهاد می‌دهد.
2. سرویس `ai` را بالا می‌آورد و مدل‌های `qwen2.5:7b` و `bge-m3` را دریافت می‌کند.
3. `COMPOSE_PROFILES=ai` را در `.env` می‌نویسد تا موتور پس از راه‌اندازی دوباره سرور هم بالا بیاید.
4. از داخل کانتینر `office-api` یک خلاصه فارسی آزمایشی می‌گیرد و زمان پاسخ را نشان می‌دهد.

سپس در رسا وارد «یکپارچه‌سازی» شوید و در کادر «هوش مصنوعی» دکمه **«Ollama همین سرور»** را بزنید. این دکمه مقادیر زیر را پر می‌کند. بعد «ذخیره» و «آزمایش اتصال» را بزنید.

| فیلد | مقدار |
|---|---|
| نشانی API | `http://ai:11434/v1` |
| کلید API | خالی |
| مدل گفتگو | `qwen2.5:7b` |
| مدل embedding | `bge-m3` (اختیاری) |

گزینه‌های دیگر اسکریپت:

```bash
CHAT_MODEL=qwen2.5:3b NEED_MB=3000 bash deploy/ai/office-llm.sh   # سرور کم‌حافظه
EMBED_MODEL= bash deploy/ai/office-llm.sh                          # فقط مدل گفتگو
```

**سرور بدون دسترسی به مخزن مدل‌ها (registry.ollama.ai):** فایل GGUF مدل را روی رایانه دیگری دریافت کنید و در `deploy/ai/models/qwen2.5-7b.gguf` بگذارید. نام فایل همان نام مدل است که `:` در آن به `-` تبدیل شده. سپس اسکریپت را دوباره اجرا کنید.

## Ollama روی سرور دیگر

اگر حافظه این سرور کافی نیست، Ollama را روی سروری در شبکه داخلی نصب کنید (مثلاً `docker run -d -p 192.168.1.x:11434:11434 -v ollama:/root/.ollama ollama/ollama` و سپس `ollama pull qwen2.5:7b`). در «یکپارچه‌سازی» نشانی `http://192.168.1.x:11434/v1` را وارد کنید. Ollama احراز هویت ندارد، پس پورت 11434 را با فایروال فقط برای همین سرور باز کنید، نه برای کل شبکه یا اینترنت.

## تنظیمات `.env`

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `AI_KEEP_ALIVE` | `5m` | مدت ماندن مدل در حافظه پس از آخرین درخواست |
| `AI_CONTEXT_LENGTH` | `8192` | اندازه پنجره متن مدل. متن نامه تا ۶۰۰۰ نویسه به مدل داده می‌شود و با پیش‌فرض کوچک Ollama بریده می‌شد. |
| `AI_NUM_PARALLEL` | `1` | تعداد درخواست همزمان. روی CPU عدد بزرگ‌تر سریع‌تر نیست و حافظه بیشتری می‌گیرد. |
| `OFFICE_AI_CHAT_TIMEOUT_SECONDS` | `300` | حداکثر انتظار رسا برای پاسخ مدل. گسترش موضوع در جستجو بیش از ۲۰ ثانیه منتظر نمی‌ماند و بدون آن ادامه می‌دهد. |

پس از تغییر: `docker compose up -d ai office-api`.

## بررسی و عیب‌یابی

```bash
docker compose exec ai ollama list     # مدل‌های نصب‌شده
docker compose exec ai ollama ps       # مدل بارگذاری‌شده و حافظه آن
docker compose logs --tail 50 ai
docker compose logs --tail 50 office-api | grep -i "ai\|summary"
```

- «آزمایش اتصال» بار اول ممکن است تا یک دقیقه طول بکشد، چون مدل باید بارگذاری شود.
- خطای `model "qwen2.5:7b" not found`: مدل نصب نشده است. اسکریپت را دوباره اجرا کنید.
- خاموش کردن: در «یکپارچه‌سازی» تیک «فعال» را بردارید. برای آزاد کردن کامل منابع، `COMPOSE_PROFILES` را از `.env` حذف کنید و `docker compose stop ai` را اجرا کنید. اگر سامانه جلسات هم از موتور استفاده می‌کند، `AI_BASE_URL=` را هم خالی کنید.
