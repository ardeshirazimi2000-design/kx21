# مشخصات سازمان و واژه‌های عمومی «جلسات»

اتوماسیون اداری «رسا» به سازمان خاصی وابسته نیست. نام و لوگوی سازمان از تنظیمات خوانده می‌شود و در رابط کاربری به‌جای «کمیسیون» واژه عمومی «جلسات» آمده است.

## مشخصات سازمان

منوی «مدیریت سیستم ← مشخصات سازمان» (مجوز `org.manage`):

| فیلد | کاربرد |
|---|---|
| نام کامل سازمان | پایین صفحه ورود، صفحه صحت‌سنجی نامه (QR)، سربرگ چاپ ساده نامه، و سربرگ قالب‌هایی که «نام سازمان» در آنها خالی است |
| نام کوتاه | اختیاری، برای جاهای کم‌جا |
| لوگو | PNG یا JPG تا ۲ مگابایت؛ در صفحه صحت‌سنجی و سربرگ قالب‌هایی که لوگوی اختصاصی ندارند |

نام و لوگو عمومی‌اند (`GET /api/org-profile` و `GET /api/org-profile/logo` بدون ورود)، چون پیش از ورود هم نمایش داده می‌شوند.

- **نصب موجود:** migration `007_org_profile.sql` نام «اتاق بازرگانی، صنایع، معادن و کشاورزی ایران» و لوگوی داخلی اتاق را نگه می‌دارد؛ ظاهر سامانه تغییری نمی‌کند تا مدیر آن را عوض کند.
- **نصب تازه:** مشخصات خالی است و مدیر سیستم پس از اولین ورود آن را پر می‌کند. سربرگ پیش‌فرض («سربرگ رسمی») نام سازمان را از همین صفحه می‌گیرد.

## واژه‌ها

| پیش‌تر | اکنون |
|---|---|
| منوی «کمیسیون‌ها» | منوی «جلسات» با «جلسات» و «پیگیری مصوبات» |
| ستون «کمیسیون» | «برگزارکننده» (نام کمیسیون، کارگروه یا شورایی که جلسه را برگزار می‌کند، همان‌طور که سامانه جلسات می‌فرستد) |
| «ارجاع به کمیسیون» | «ارجاع به جلسه» |
| «ابلاغ مصوبه ۱۲ کمیسیون کمیسیون تجارت» | «ابلاغ مصوبه ۱۲ کمیسیون تجارت» (نام برگزارکننده خودش واژه کمیسیون را دارد) |
| فرایند «پیگیری اجرای مصوبه کمیسیون» | «پیگیری اجرای مصوبه جلسه» |
| نقش «رئیس اتاق / معاون» | «رئیس سازمان / معاون» |

نام‌های پیش‌فرض (فرایند، نقش، اتصال سامانه جلسات) فقط اگر دست نخورده باشند به‌روز می‌شوند. قالب اعلانی که مدیر ویرایش کرده دست نمی‌خورد؛ متغیر `{{commission}}` همچنان نام برگزارکننده است. نامه‌هایی که پیش‌تر ثبت شده‌اند تغییر نمی‌کنند.

**بدون تغییر:** ستون‌های `commission_id` / `commission_name` در پایگاه داده، قرارداد API با سامانه جلسات (`/commissions`، `commissionId`) و خود سامانه جلسات (`apps/api`، `apps/web`).
