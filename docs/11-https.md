# ۱۱. HTTPS برای سامانهٔ کمیسیون‌ها (الزام ۲-۹ سند افتا)

ارتباط مرورگر و برنامهٔ موبایل با سامانه باید رمزنگاری‌شده باشد. ظرف وب سامانه خودش HTTPS می‌دهد؛ پورت HTTP فقط به HTTPS هدایت می‌کند و ورود از طریق HTTP ساده رد می‌شود (`https_required`). طراحی همان طراحی اتوماسیون اداری است (`docs/office/05-https.md`).

| بخش | رفتار |
|---|---|
| `web` (nginx) | با `KX_TLS=1` روی ۴۴۳ داخل کانتینر HTTPS؛ فقط TLS 1.2 و 1.3 و مجموعه‌رمزهای ECDHE با AES-GCM (فهرست الزامات TLS سند افتا). پورت ۸۰ با کد ۳۰۱ به HTTPS می‌برد. سرآیندهای امنیتی و HSTS. |
| `web` (nginx) | `X-Forwarded-For` و `X-Forwarded-Proto` مرورگر دور ریخته می‌شود؛ فقط پراکسی‌های `KX_TRUSTED_PROXIES` می‌توانند نشانی کاربر و HTTPS بودن را اعلام کنند. |
| `api` | با `PUBLIC_HTTPS=true` مسیرهای `/api/auth/*` روی HTTP رد می‌شوند، پیش از بررسی رمز. `TRUST_PROXY` تعیین می‌کند به کدام پراکسی اعتماد شود (پیش‌فرض یک گام: nginx همین سامانه). |

## روشن کردن روی نصب Docker فعلی

```bash
cd ~/kx21 && git pull
bash deploy/tls/enable-https.sh
```

* اگر گواهینامهٔ رسمی ندارید، یک **گواهینامهٔ داخلی** ساخته می‌شود (پوشهٔ `/root/kx21-tls`، بیرون از مخزن).
* HTTPS روی پورت `8443` است (`HTTPS_PORT=9443 bash deploy/tls/enable-https.sh` برای پورت دیگر)؛ پورت فعلی (`8000`) از این پس فقط به HTTPS هدایت می‌کند.
* اطلاعات دست نمی‌خورد. پورت را در فایروال باز کنید: `sudo ufw allow 8443/tcp`.
* اگر Caddy یا وب‌سرور دیگری جلوی سامانه است، نشانی آن را در `KX_TRUSTED_PROXIES` بدهید.

## بستهٔ نصب آفلاین

نصاب بسته خودش گواهینامهٔ داخلی می‌سازد و سامانه را فقط روی HTTPS پورت ۵۰۰۰ بالا می‌آورد: `https://نشانی-سرور:5000`. برای گواهینامهٔ رسمی، پیش از نصب `fullchain.pem` و `privkey.pem` را در `/opt/kx21/tls` بگذارید.

## گواهینامهٔ داخلی و نصب آن روی دستگاه‌ها

`deploy/tls/make-cert.sh` یک‌بار یک «مرجع صدور» مخصوص همین نصب می‌سازد (`kx21-ca.crt`، ده سال) و گواهینامهٔ سرور را با نام‌ها و نشانی‌های سرور امضا می‌کند (۸۲۵ روز؛ کلید منحنی بیضوی P-256). تا وقتی `kx21-ca.crt` روی دستگاه نصب نشود، مرورگر هشدار امنیتی نشان می‌دهد و برنامهٔ موبایل وصل نمی‌شود. کلید مرجع (`kx21-ca.key`) هرگز نباید از سرور خارج شود.

| دستگاه | نصب `kx21-ca.crt` |
|---|---|
| ویندوز | دوبار کلیک روی `kx21-ca.cer` ← Install Certificate ← Local Machine ← «Trusted Root Certification Authorities»؛ سپس مرورگر را ببندید و باز کنید. |
| اندروید | فایل را به گوشی بفرستید؛ تنظیمات ← امنیت ← رمزگذاری و اطلاعات کاربری ← نصب گواهی ← «گواهی CA». برنامهٔ موبایل از نسخهٔ ۱٫۱٫۰ این گواهی را می‌شناسد. |
| آیفون | فایل را باز کنید و نمایه را نصب کنید؛ سپس تنظیمات ← عمومی ← درباره ← تنظیمات اعتماد به گواهی ← روشن کردن آن. |
| Firefox | تنظیمات ← حریم خصوصی و امنیت ← مشاهدهٔ گواهی‌ها ← مراجع ← درون‌ریزی. |

برای افزودن نام یا نشانی جدید (یا تمدید)، `bash deploy/tls/make-cert.sh /root/kx21-tls نام-یا-نشانی …` را دوباره اجرا و `docker compose restart web` کنید؛ مرجع صدور تغییر نمی‌کند و دستگاه‌ها لازم نیست دوباره گواهی نصب کنند.

## گواهینامهٔ رسمی (پیشنهادی)

بهترین راه یک زیردامنه از دامنهٔ اتاق (مثلاً `commissions.<دامنهٔ اتاق>`) و گواهینامهٔ رایگان Let's Encrypt یا گواهینامهٔ تجاری است؛ آن‌وقت هیچ نصبی روی دستگاه‌ها لازم نیست. `fullchain.pem` و `privkey.pem` را به‌جای فایل‌های داخلی در `KX_TLS_DIR` بگذارید و `docker compose restart web` کنید.
