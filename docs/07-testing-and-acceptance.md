# ۷. تست و معیارهای پذیرش

| سطح | محل | اجرا |
|---|---|---|
| Unit (قواعد کسب‌وکار) | `packages/shared/src/shared.test.ts` — state machine، نصاب، آرا، مجوزها، تقویم شمسی | `npm test -w @kx/shared` |
| Integration + E2E API | `apps/api/test/meeting-lifecycle.test.ts` — PostgreSQL واقعی + Socket.IO واقعی، چرخه کامل جلسه | `npm test -w @kx/api` (نیازمند PostgreSQL؛ `TEST_DATABASE_URL`) |
| E2E مرورگر | در توسعه با Playwright اجرا شد (وب و نسخه وب اپ موبایل)؛ اسکریپت دائمی در Backlog | — |
| CI | `.github/workflows/ci.yml` — typecheck، تست‌ها، build وب و API، typecheck و bundle موبایل | خودکار |

## نگاشت معیارهای پذیرش به تست‌ها

**اعلام حضور (بخش ۲۰):**
| معیار | پوشش |
|---|---|
| فقط دعوت‌شده/مجاز | کارشناس دعوت‌نشده 404؛ قابلیت `attendance.self` |
| timestamp | `checked_in_at` بررسی می‌شود |
| بدون رکورد تکراری | اعلام دوباره ⇒ 200، همان زمان، یک رکورد |
| اصلاح با دلیل | بدون دلیل 400، با دلیل 200 + Audit |
| بدون Refresh | دریافت `attendance.updated` روی سوکت دبیر |
| تعداد و نصاب | `quorum.required = 5` برای ۸ عضو دارای رأی |
| بسته‌شدن Check-in | اعلام حضور پس از پایان جلسه ⇒ 409 |
| Audit | ورودی `attendance.corrected` |

**اجرای جلسه (بخش ۲۱):** فقط جلسه زمان‌بندی‌شده شروع می‌شود (شروع دوباره/جلسه لغوشده ⇒ 409)، زمان و کاربر شروع ثبت می‌شود، فقط یک آیتم فعال، رأی‌گیری فقط توسط نقش مجاز (عضو ⇒ 403)، تغییر رأی پس از بستن ⇒ 409، پایان جلسه ⇒ پیش‌نویس صورتجلسه، تأیید ⇒ نسخه قفل (تلاش ویرایش ⇒ 409 و تریگر DB).

**سایر موارد بخش ۲۲:** هم‌زمانی رأی‌ها (۵ درخواست موازی)، Permission بین کمیسیون‌ها، اعتبارسنجی آپلود (فایل جعلی PDF رد می‌شود)، زنجیره Audit و append-only، چرخش Refresh token، یادآوری یک‌باره تأخیر مصوبه، Export محدود به مجوز.

موارد باقی‌مانده برای QA: تست Push روی دستگاه واقعی، تست قطع/وصل شبکه روی دستگاه، تست بار (k6 روی سناریو اعلام حضور و رأی با چند صد کاربر)، تست نفوذ.
